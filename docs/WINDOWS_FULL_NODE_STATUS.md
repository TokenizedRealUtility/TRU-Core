# Native Windows full-node status

The supplied source is not yet a native Windows full node. GUI-DESKTOP-01 deliberately leaves consensus, wallet-persistence and P2P implementation unchanged. WINDOWS-DESKTOP-01 builds a separate Qt RPC client.

## Why the old build fails

| Existing source/build issue | Required full-node correction |
|---|---|
| `windows_CMakeLists.txt` mixes hardcoded i686 paths, a stale common-source list and manual dependencies | Use one canonical production source list and one x86_64 target dependency prefix |
| Cross build disables AUTOMOC | Use Linux-hosted Qt MOC/RCC tools compatible with the target Qt build; do not run Windows tools on Linux |
| Dummy `Threads::Threads` and optional missing crypto libraries | Use real imported dependency targets and a consistent threading runtime; required dependencies must fail closed |
| `main.cpp` POSIX poll/self-pipe, sigaction, SIGWINCH, termios, ioctl | Implement Windows console events, interruptible stdin and hidden password input; preserve graceful shutdown |
| `main.cpp` fork/exec/waitpid/kill miner manager | Implement Windows process ownership and graceful termination (or a shared cross-platform process abstraction) |
| `p2p.cpp`, `peer_connection.*` POSIX sockets, pipe/select, fcntl, close and errno | Winsock initialization, SOCKET-width storage, WSA errors, closesocket, ioctlsocket, proper select wakeup and socket lifetime |
| `network_identity.h`, `miner_telemetry_v1.h` POSIX network headers/interface discovery | Implement Windows interface enumeration/address normalization with parity for self-peer filtering |
| `wallet.cpp` O_DIRECTORY, fsync, create-exclusive and rename journals | Windows authenticated wallet persistence using correctly restricted files, durable writes and atomic replacement; exercise every recovery phase |
| `rpc_utils.h` Windows permissions branch | Verify actual Windows ACL confidentiality, not just POSIX-style permission bits |
| `utils.cpp`, `wallet_cli.cpp`, `leveldb_storage.cpp` POSIX input and filesystem calls | Explicit portable terminal/directory paths, keeping security semantics intact |
| Checked-in protobuf code generated by 3.21.12 | Match target protobuf and the host protoc generator, or regenerate in the build tree from the unchanged `.proto` |
| libwally, ethash/keccak, LevelDB, crc32c, curl/OpenSSL, sodium, protobuf, fmt/json dependencies | Build all for the same Windows architecture/compiler/CRT and account for transitive link dependencies |

Do not define Linux calls away, make fsync a no-op, treat a Windows SOCKET as a 32-bit int, suppress failed crypto-library discovery, or copy Linux libraries into a Windows link. Those changes can produce broken runtime behavior even if compilation progresses.

## Recommended implementation order

1. **WIN-CORE-01 platform abstraction:** sockets, wakeups, terminal input, process lifecycle and durable file operations. Keep the Linux backend behavior unchanged.
2. **WIN-DEPS-01 dependency build:** pinned Windows dependencies, matching host protoc, real target exports and a single production source list.
3. **WIN-CORE-02 build:** headless node, tru-cli and CPU miner first. Qt full-node integration and OpenCL follow after that baseline works.
4. **WIN-VERIFY-01:** clean Windows test VM; genesis and transaction vectors identical to Linux; P2P handshake/sync; malformed input rejection; encrypted wallet bootstrap/unlock/persist/restart; journal crash recovery; Ctrl+C and GUI-close shutdown; child-process teardown.
5. **WIN-RELEASE-01:** dependency packaging, license notices, clean-machine runtime, reproducible manifest, checksums and release artifacts.

These are proposed next patches, not changes included in this package. The portable desktop client and existing Linux core can be built independently while this work is completed.

Primary build references: [CMake toolchains](https://cmake.org/cmake/help/latest/manual/cmake-toolchains.7.html), [MXE](https://mxe.cc/), [Qt Windows deployment](https://doc.qt.io/archives/qt-5.15/windows-deployment.html).
